## Sen 定下的硬约束（高于一切推荐）

1. 完整复刻 SketchUp 建模工具 + 建模逻辑 + 工具菜单。
2. 适配 Blender 4.x–5.x。Extension 格式要求 `blender_version_min` 不低于 4.2.0，因此“4.x”实际指 4.2+（见决策 D6，含 4.0/4.1 需另议）。每阶段验收都须在 4.x 线（4.5 LTS 为代表）与 5.x 线（Sen 的 5.1.2 + 5.2 LTS 为代表）上验证安装运行，不能只验一个版本。
3. 界面语言跟随 Blender 的语言设置，用 Blender 自带翻译机制实现，不写死语言；中/英文至少都要能跟随（机制见 §5.8，验收见各阶段）。
4. 每阶段交付可安装的 `.zip` + 测试说明；每阶段验收都含 Sen 在 5.1.2 真机上的手工清单。

## 版本基线（重要）

Help Center 页面已混入 SketchUp 2027 内容（2027.0，27.0.264，2026-10-22 发布）：Procedural Follow Me、Procedural Solid Tools（Union / Subtract / Intersect）、Copy Along、AutoFit Live Components 均为 2027 新增，Sen 的 26.0.429 没有。本方案基线为 **2026 classic 行为**，2027 新增功能一律列入“范围外 / 待 Sen 定”（决策 D2），不写进规格。判定依据：Ruby API Release Notes（Procedures API 为 SU2027.0 新增）。

### 1.6 实体布尔 Solid Tools（6，Pro）

共通前提：Solid = 有限闭合体积的组/组件。预选后右键执行，或先激活工具再依次点选；Union / Outer Shell 结果成为一个 Group。均无默认快捷键、无 VCB/推断。

| 工具 | 行为 | 点选顺序 |
|---|---|---|
| Outer Shell | 只保留重叠实体外表面，删除内部几何（含内部空腔） | 任选 ≥2 个，可追加 |
| Union | 合并 ≥2 个实体为单一实体，保留重叠处内部空隙 | 任选 ≥2 个，可追加 |
| Subtract | 第一实体切第二实体，切削体被删除 | 先选切削体，再选被切体 |
| Trim | 同 Subtract，但切削体保留 | 同上 |
| Intersect | 只保留重叠部分几何 | 任选 ≥2 个 |
| Split | 沿相交边分割重叠实体 | 选第一实体，再选相交的第二实体 |

Solid 的精确判定规则。Procedural 变体属 2027，基线外（D2）。

## §2 工具菜单完整复刻规格

### 2.1 复刻边界（先说清，再谈结构）

Blender 不允许插件替换主菜单栏。SketchUp 的 File / Edit / View / Camera / Draw / Tools / Window / Extensions / Help 整条菜单栏无法 1:1 搬过来。本方案中“完整复刻工具菜单”指：**Tools 菜单 + Draw 菜单 + Camera 菜单（建模相关部分）+ Large Tool Set + 建模右键菜单**的完整复刻，落点见 §2.4。此边界须 Sen 确认（决策 D3）。File / Edit / Window 等应用级菜单不复刻（Blender 原生已有对应功能）；Edit 菜单中与建模直接相关的命令（Make Group / Make Component / Explode / Hide / Delete Guides 等）随右键菜单与工具逻辑一并实现。

## §3 建模逻辑核心规格

核心判断（→ 调研 B 总览）：**SketchUp 的“灵魂”在推断引擎 + 自动成面/粘性几何 + 编辑上下文三件套，Blender 均无原生等价物，必须自研。bmesh 只提供拓扑操作原语，不提供 SketchUp 语义。** 任何“调几个 `bpy.ops` 就能复刻”的预期都不成立。

根架构（→ 调研 B §6.2 / §10）：**一编辑上下文 = 一个 Mesh Object**（上下文内全部散几何存在同一个 Mesh 里，共享顶点即粘连）；Group = 独立 Mesh 的 Object；Component = 多 Object 共享同一 Mesh 数据块（Linked Duplicate 语义）；工具一律在 Edit Mode 下用 `bmesh.from_edit_mesh` 操作活动上下文（→ 调研 B §10.3 定稿：Edit Mode 一次一对象，天然对应单上下文编辑；Object Mode 数据在编辑中不同步，拾取不可用）。Blender 与 SketchUp 同为 Z-up，坐标方向一致，无须变换。

### 3.1 推断引擎 Inference（最难，★★★★★）

**SketchUp 定义（官方，→ 调研 B §1.1 / 调研 A §4.1）：** 三大类——点推断 13 种（Origin、Component Origin、Endpoint、Midpoint、Arc Midpoint、Intersection、On Face、On Edge、Center、Guide Point、On Line、On Section、Intersection with Hidden Section）；线性推断 8 类（On Red/Green/Blue Axis、From Point、Through Point、Parallel、Extend Edge、Perpendicular、Perpendicular to Face、Tangent at Vertex）；形状推断 5 类（Square、Golden Section、Half/Quarter/Three-Quarter Circle、Arc Side and Center、Circle/Polygon Center）。推断常组合成复合推断。悬停鼓励：光标停在某点后，SketchUp 优先与该点对齐。锁定：↑ 蓝轴、← 绿轴、→ 红轴、↓ 平行/垂直（洋红）；Shift 按住锁定当前推断方向/平面；Shift+Alt 锁定平面的同时锁定到同一推断面；Line 工具 Alt 循环切换线性推断三态（All On → All Off → Parallel/Perpendicular Only）。组/组件内部几何的推断显示为洋红色。**长度/角度没有独立的官方推断类型**，精确控制归 VCB + Length/Angle Snapping（§3.9），不要虚构“长度推断”类型。

**Blender 映射（自研，→ 调研 B §1.2）：** Blender 内置 Snap 语义完全不同（无 From/Through/Parallel/Perpendicular/Extend/形状推断，无锁定状态机，无 ScreenTip），不复用。自研引擎 = BVH 拾取 + 候选生成 + 锁定状态机 + GPU 绘制：

- 拾取：`bpy_extras.view3d_utils.region_2d_to_origin_3d / region_2d_to_vector_3d` 得射线；`mathutils.bvhtree.BVHTree.FromBMesh` + `ray_cast` 求命中（Edit Mode 下须用 BMesh 的 BVH，`Object.ray_cast` 读未同步数据不可用）；跨上下文拾取须双源（活动 bmesh + 其他对象 Mesh，世界/局部坐标换算）。
- 候选生成（每帧）：点候选（射线附近屏幕阈值内的顶点/边中点/圆心/交点/面上点/边上最近点）、线性候选（与三轴/已有边方向/悬停参考点求夹角与共线）、形状候选（仅 Rectangle / Arc 等工具内注入）。优先级：点推断 > 线性推断 > 自由面点；悬停鼓励用“悬停停留加权”实现（停留阈值无官方值，须调参、真机体感验收）。
- 锁定状态机：独立模块，状态 = {无锁定， 轴锁定（R/G/B）， 洋红锁定， Shift 锁定， 平面锁定}；方向键按下锁定、再按同键解除；Shift 按住锁定、松开解除。锁定后鼠标移动只改变沿锁定方向/平面的参数。
- 绘制：推断标记、推断虚线、ScreenTip 文字用 `gpu` + `blf` 绘制；标记颜色/形状做成主题常量表（颜色须真机截图核对，见下）。

**难点与取舍：** ① 复合推断（两阶段求解：锁定第一约束后在约束线上求第二约束交点）分阶段做，先单约束 + 轴锁定 + From Point，再双约束交点。② 推断图标颜色：官方正文只明确 Midpoint 为浅蓝（light blue dot），其余颜色来自 2006 年旧手册/社区教程等二手来源，实现时颜色须做成可配置常量，绝不写死。③ 圆/弧中心推断依赖曲线实体元数据（§3.10），第一阶段只对插件工具画的圆/弧生效，导入网格无效，须明说。④ 参考线（Guide）须独立实体类型与拾取通道，不进 Mesh、不参与成面。⑤ 性能：大模型下须空间索引（BVH + 屏幕空间候选裁剪）+ 脏标记缓存，禁止每帧全量候选。

### 3.2 面的生成与愈合（粘性几何，★★★★☆）

**SketchUp 定义（官方，→ 调研 B §2.1）：** 边与面是基本实体；几条线连成形状即形成面（同一平面内的闭合环生成面——“共面”二字官方词条未逐字写出，为几何前提 + 论坛共识，措辞上标注来源级别）；面上画线分割面；删边连带删相邻面（右键面 Erase 只删面）；删分隔线/弧则面愈合为整面；误删面后重画导致面消失的那条线即可恢复面；新线与已有线相交即自动分裂已有线；Divide 等分、Weld 生成 Curve、Explode Curve 打散。同一上下文内边/面相互粘连（Sticky），只有组/组件容器能隔离。

**Blender 映射（自研成面/愈合引擎，→ 调研 B §2.2）：** Blender Mesh/bmesh 没有自动成面（`edgenet_fill` 只填充指定边网，不监听拓扑变化）。每次几何编辑后运行增量成面：取受影响边 → 拟合平面（容差可配）→ 平面内 2D 投影做环检测找最小闭合环 → 对未成面且共面的环 `bm.faces.new` 建面（环内有弦时先找最小环，自然得到子面）；删分隔边时检查两侧面共面可合并则愈合（`dissolve_faces` 或手动删两面建一面）；删边时显式处理 `edge.link_faces`（bmesh 删边默认不连带删面，须自处理）；新边与同平面已有边相交时在交点分裂已有边与新边（交点顶点合并，容差内视为同点），此为成面前置步骤。新面法线取确定性规则（朝向当前视图/上方），规则须写明并请 Sen 验收，提供 Reverse Faces 修正。

**难点与取舍：** ① **Blender 面不支持洞**（bmesh 无 HOLES 支持）：SketchUp 的带洞面（带内环的面）须用“多面 + 逻辑面 ID”模拟——插件内部以“面片集合 + 逻辑面 ID（面自定义层）”表达带洞面，显示/选择时按逻辑面合并处理；内环须与外环通过分裂边连接，或以外环减内环三角化再合并。此为面模型语义的根本差异，必须在规格中明确。② 环检测 + 共面判定 + 弦分割须增量化（只重算受影响平面/连通域），全模型检测在大模型下不可行。③ 浮点容差：Blender 坐标 float32，SketchUp 为 double，容差须按场景尺度自适应（§3.9）。④ Undo 粒度：成面/愈合须与触发编辑合并为一次 Undo（§5.7）。⑤ 成面环优先级（大环套小环、重画边后愈合顺序）官方未述，采用“合理确定性算法 + 重点场景真机对比”（D15）。⑥ 最小边长/清理阈值（社区常说约 0.001 英寸）官方未给数值，**不写入规格数值**，以可配置合并距离处理。

### 3.3 推拉 Push/Pull（★★★★☆）

**SketchUp 定义（官方，→ 调研 B §3.1 / 调研 A §5.3.2）：** 任意面拉成 3D 体或从模型切掉一块；拉出后在选他物前可输精确距离修改；双击另一面以相同距离复制挤出，Ctrl+双击在现有挤出上叠加相同挤出；推入到 “offset is limited” 即完全贯穿。官方词条**未提及**以下社区熟知行为，须标注为二手/待核（D14）：Ctrl 保留起始面生成新面、推拉到其他面/点对齐、曲面多面推拉差异、推拉遇非平面/自交的失败行为。

**Blender 映射（→ 调研 B §3.2）：** 基础挤出推荐手动建侧面（语义可控：侧面材质/边 soft/smooth 继承、起始面保留与否），`bmesh.ops.extrude_face_region`（本身不位移，须另调 `translate`）作对照。交互为 Modal：点面高亮 → 拖动实时预览（距离 = 鼠标射线在法线上的投影 + 推断修正）→ VCB 覆盖距离 → 点击确认；保存上次推拉距离供双击复用。**推入打洞/封口为关键自研逻辑**：向内推时计算挤出面与模型其他面的交点，到达对侧面时删除被推出部分并愈合开口（bmesh 内受限布尔，仅处理“挤出棱柱 vs 单个体”，不直接调 Boolean 修改器——会改变拓扑所有权与材质/选择语义且对非流形失效）；到达对侧面平面时锁定距离上限并显示 “offset is limited” 提示。

**分阶段：** 第一阶段先做“拉出 + 推入（不穿透）+ 双击复用”，“推穿打洞”作为后一阶段验收项（§6 阶段 P3/P4）。

### 3.4 跟随路径 Follow Me，classic（★★★★☆）

**SketchUp 定义（官方 classic，→ 调研 B §4.1）：** 截面沿路径生成 3D 形体；截面须大致垂直于路径（不必相连）；自动挤出：预选连续边作路径 → 激活工具 → 单击截面（路径与截面须同一上下文）；手动挤出：单击拖拽截面沿路径走，触到路径时路径高亮为红；圆路径可车削回转体。角部处理细节（内外角斜接、尖角拉伸/截断、急转弯自交、非严格垂直投影规则）官方词条**未述**，须自定算法并真机对比，不得声称“按官方算法”。

**Blender 映射（自研放样，→ 调研 B §4.2）：** Blender 无等价算子。算法：轮廓面（外环顶点序列 + 平面法线）+ 有序边链路径 → 沿路径每段计算轮廓帧（切线为前进方向，平行移动防扭转，顶点处角平分面 miter 求交）→ 每段生成侧面四边形带，首尾封口，闭合路径首尾缝合；轮廓环带洞暂不支持。角部策略：外角 miter 延伸设最大延伸比（超限截断为 bevel，K 值无官方依据，调参验收）；内角裁剪重叠并愈合；锐角自交时裁剪 + 状态栏提示（取舍见决策 D14 备注：静默裁剪还是提示失败，默认裁剪+提示）。侧面继承轮廓面材质；Curve 路径分段边置 soft+smooth，折线路径保持硬边。车削为闭合圆路径特例，统一处理。

**分阶段：** 先做自动模式，手动模式（鼠标划过路径识别、边序推断、回退、分支选择）后补（§6）。

### 3.5 偏移 Offset、交线 Intersect Faces、柔化/平滑边

**Offset（★★★☆☆，→ 调研 B §5.1）：** 画与原形状等距的稍大/稍小版本；偏移线须预选 ≥2 条相连共面线，偏移面直接点面；换工具前可反复重置距离。偏移极限、Ctrl 绕过极限、双击重复。映射：`bmesh.ops.inset_region` / `offset_edgeloops` 语义与 SketchUp 不完全一致，须逐项对照测试后决定复用或自研（自研备选：平面内 2D 多边形偏移，直线段平移 + 角点求交 + 自交裁剪；弧离散为折线后偏移，标记为不可编辑 Curve）。

**Intersect Faces（★★★★☆，→ 调研 B §5.2）：** 在两组面相交处生成新边；三档：With Model（模型中其他所有面，含嵌套容器内）、With Context（仅当前上下文内其他面，仅打开容器编辑时可用）、With Selection（与第一组相同选择，须预选多面）。新边始终放在当前活动编辑上下文中。**来源级别注意：Help Center 无独立专篇，定义来自 Entity Context Menus 词条 + 论坛版主级说明，须 Sen/真机复核。** 映射：无等价算子（`bisect_plane` 只能平面切割，Boolean 修改器不等价于“只生成交线、不删改原面”）；自研两组面逐对求交（三角化后三角-三角求交或平面求交线 + 线段裁剪）→ 交线段去重/合并 → 在交点处分裂原面并由成面引擎重建被切面；BVH 裁剪候选对；跨上下文求交处理对象变换矩阵（世界 ↔ 局部）。

**Soften / Smooth / Hide（★★★☆☆，→ 调研 B §5.3）：** 三个独立边属性：Soft = 边隐藏 + 相邻面成一个 Surface 实体（选一面即选整个 Surface）；Smooth = 加着色使面平滑，单独应用时边仍可见；Hide = 边不可见但相邻面不成 Surface。Eraser+Ctrl 同时 Soft+Smooth；Soften Edges 对话框按法向夹角阈值批量处理。映射：Smooth 用 `BMEdge.smooth` + `BMFace.smooth`（4.1+ 已移除 `use_auto_smooth`，改按边 Sharp + 面 Smooth 体系，锁定版本后复核 current 文档，不得沿用旧写法）；Soft/Hide 用边自定义层存标志 + 自研绘制/选择逻辑（Soft 边两侧面点选时沿 Soft 边 flood fill 选中整个 Surface；Hidden Geometry 模式下以虚线显示且可单独选面）。右键 Soften 是否同时 Smooth。

### 3.6 组 Group 与组件 Component（★★★☆☆）

**SketchUp 定义（官方 + 论坛共识，→ 调研 B §6.1 / 调研 A §5.10）：** Group = 一组几何的选择集合，副本各自独立；Component = 定义（Definition）+ 实例（Instance），编辑任一实例更新全部实例与定义；Make Unique 使实例脱离原定义；Explode 解散容器、内容回到父上下文（可能重新粘连）；容器隔离粘性、可嵌套；双击进入编辑上下文（其余模型变淡、边界变虚线），点空白处或 Close 退出；Outliner 树形显示组/组件/剖面，可导航、命名、重组层级、控制可见性；组件可改轴、Glue to 面、Cut Opening（开洞）。

**Blender 映射（→ 调研 B §6.2）：** 见本节开头根架构表。Group 副本直接深拷贝（`obj.copy()` + `data.copy()`，不模拟 SketchUp 内部“编辑时自动分裂”，行为等价且简单）；Make Unique = `obj.data = obj.data.copy()`；Explode = 容器内几何经变换矩阵合并入父上下文 Mesh + 删容器对象（处理材质槽合并 + 成面重算）；嵌套用 Object 父子链；编辑上下文 = 插件维护的 `active_context` 对象栈（工具只读写该对象 Mesh，进入/退出 = 切换活动对象 + 其余对象淡显 + 锁定非上下文对象选择）；组件原点/轴 = Object 原点 + ID Property 自定义轴。

**嵌套组件暗坑（必须单列）：** 单 Mesh 无法表达“定义内含子组件实例”。含嵌套内容的组件定义须用 Collection + Collection Instance 表达（定义 = 一个 Collection，实例 = Collection Instance / 整树 Linked Duplicate）；Collection Instance 不可直接编辑内部几何，须自研“双击实例跳转到定义 Collection 编辑”的流程，与 SketchUp“双击任一实例进入定义编辑”有交互差异。**取舍须 Sen 确认（决策 D7）**，备选：限制嵌套深度、或组件内只允许散几何。Glue / Cut Opening 第一阶段不支持（创建对话框先不做该选项或明示未实现）。Dynamic / Live Components 范围外（D11）。

### 3.7 材质 Materials（★★★★☆）

**SketchUp 定义（→ 调研 B §7.1）：** Paint Bucket 可预选或直接点面/边上材质；容器上材质时，面有直接材质则面材质优先显示、无直接材质则显示容器材质；取样 Alt+Paint Bucket；替换模式：All Matching（Shift，全模型同材质）、All Connected（Ctrl，相连同材质）、All on Same Object（Ctrl+Shift，同一组/组件内同材质）；每面有正反面（默认正面白、反面蓝灰），材质可分别赋予正反面；贴图坐标每面独立存 UV，Texture Position 四钉模式（红锚点、绿缩放/旋转、蓝剪切、黄扭曲；Fixed/Free Pins；Projected 投影模式）；材质有真实世界尺寸，按真实尺寸平铺。

**Blender 映射（→ 调研 B §7.2）：** 材质载体 = `Material` 数据块 + Mesh 材质槽 + 每面 `material_index`；SketchUp 材质（颜色/纹理/透明度/真实尺寸）→ Principled BSDF 节点树；UV = Loop UV（`bm.loops.layers.uv`），每面独立 UV 天然对应，真实尺寸平铺 = 世界坐标/纹理尺寸投影生成初始 UV，四钉 = 自研 Modal 工具改 Loop UV（Free Pins 透视须单应性矩阵）；容器材质 = Object 级材质槽（`link='OBJECT'`），显式处理优先级（面材质 > 对象材质 > 默认）。

**正反面双材质（核心取舍，决策 D8）：** Blender 面只有一个 `material_index`，无原生正反面双材质。备选：B 自定义层法（推荐：`material_index` = 正面，面自定义 int 层 = 反面，视口自研绘制区分；代价是原生视口/渲染只认正面，反面材质仅插件视图模式可见）；C 几何节点/着色器法（Backface 判断 + 双材质混合，编辑拾取仍须自研正反面区分）。**须问 Sen 反面独立材质是否为刚需**；默认第一阶段只做正面材质 + 反面统一默认色显示。

### 3.8 剖面 Section Plane、标签 Tags、场景 Scenes、样式 Styles

**Section Plane（建模相关度中，→ 调研 B §8.1）：** 纯显示行为，不改几何；每 Context 只有一个活动切割；创建点面放置、Move/Rotate 调整、右键 Reverse/Align View/Active Cut；Section Fill（Styles 面板开关，须组/组件层级内闭合环）；Create Group from Slice（生成剖面交线处的成组几何，仅边无面）；Display Section Planes 与 Display Section Cuts 两档独立控制。映射：剖面实体 = Empty + ID Property（名称、编号、活动/反转标志），归属 Context = 父级容器，活动唯一性由插件状态机保证；切割显示推荐自研 GPU 裁剪（clip plane 着色器，只影响显示不改数据），备选 Boolean 修改器（影响求值网格，编辑时须临时禁用）；Slice 用 `bmesh.ops.bisect_plane`（不清除内外，取交线）或自研平面-面求交。里程碑：先做放置 + 切割显示 + Active Cut/Reverse/Hide + Create Group from Slice；Section Fill 与导出延后/范围外。

**Tags（建模相关度中，→ 调研 B §8.2）：** 旧版 Layers 的更新形式；默认新建几何 Untagged；可给面/边打 Tag 但最佳实践只打在组/组件上；Tags 面板含 Add Tag、Tag Folder（可嵌套）、Filter、Tag 工具、Color by Tag、Dashes、Material（每 Tag 一材质）等；Tag 工具修饰键 Sample / Replace All / Tag All Instances。映射：**Tags ≠ Collections**（Collection 是层级容器，与容器嵌套冲突；Tag 是正交维度）。推荐：Scene 级 Tag 列表（PropertyGroup Collection）+ 每对象一个 `tag` ID Property；可见性 = 按 Tag 批量设 `hide_viewport`；Color by Tag = 临时覆盖 `Object.color`；Dashes 延后。第一阶段只支持对象级 Tag，面/边级 Tag 不支持并明说（须 Sen 确认，见 D15 备注）。

**Scenes（建模相关度低，→ 调研 B §8.3）：** 保存视图与属性（Camera Location、Visible Tags、Active Section Planes、Style and Fog、Shadow Settings、Environment、Axes）。映射：Scene 级快照列表（相机位姿 + Tag 可见性 + 活动剖面 + 隐藏对象 + 样式选项），**不得用多 Blender Scene 表达 SketchUp Scenes**（会分裂数据）。判断：延后，第二阶段后，第一阶段只预留数据结构。

**Styles（仅显示项相关，→ 调研 B §8.4）：** 只复刻影响建模判断的显示项：边显示（Edges 开关、By Axis 着色、端点显示）、面样式（Shaded / Shaded with Textures / Wireframe / Hidden Line / X-Ray）、Hidden Geometry 显示、剖面开关。映射：视口着色模式 + Overlay 开关 + 自研边绘制（By Axis、X-Ray 须自研，原生 Overlay 不直接提供）。其余（手绘边、雾、阴影、水印）范围外。

### 3.9 坐标与单位

**SketchUp（→ 调研 B §9.1）：** 红=X、绿=Y、蓝=Z，Z-up；绘图轴可移动/重定向，推断轴随绘图轴走——推断引擎须支持自定义绘图轴（原点 + 三方向），不能写死世界轴。单位设置（Model Info > Units）：Format、Length/Area/Volume 单位、Display Precision、Enable Length Snapping、Enable Angle Snapping；改单位只改显示不改几何。VCB 解析须支持：十进制、分数、英尺-英寸（如 `6' 8 7/8"`）、单位后缀、负数、分隔符（工具相关格式归调研 A 各工具 VCB 规格）。

**Blender 映射（→ 调研 B §9.2）：** 插件内部统一用米（Blender 单位）存储，显示/输入层做单位换算，不得改 `scale_length`。**精度：** Blender Mesh/bmesh 坐标为 float32，SketchUp 为 double；容差 = max(绝对容差, 相对容差 × 场景尺度)，建议原点附近建模；“双精度影子模型”第一阶段不用（先验证 float32 在 Sen 实际模型尺度下是否够用，D15）。Length/Angle Snapping 自研（VCB 输入后/鼠标移动时按增量取整）；Length Snapping 默认开/关与默认单位模板须 Sen 定（D15，默认：关 + 毫米模板，供 Sen 改）。绘图轴存 Scene 级自定义轴，推断与 VCB 坐标输入均以它为基准。

### 3.10 数据模型总映射与关键取舍（摘要，全表 → 调研 B §10）

| SketchUp 概念 | Blender 表达 |
|---|---|
| Model | `.blend` + 一个 Scene |
| Edge / Vertex / Face（含内环） | `BMEdge` / `BMVert` / 1 个或多个 `BMFace` + 逻辑面 ID（面自定义层） |
| Curve / Arc / Circle / Polygon | 边集合 + 曲线元数据（边自定义层 `curve_id` + 对象/场景级字典：类型、中心、半径、段数、平面、起止角）；Explode Curve = 删元数据；原生工具改边后元数据失效则降级为散边（校验后不报错） |
| Surface（Soft 边连成的面组） | Soft 边连通域（运行时计算）+ 选集扩展，无独立数据块 |
| Group / Component | 见 §3.6；嵌套组件见 §3.6 暗坑 |
| Guide Point / Line | 独立 Empty / 自定义绘制 + 插件数据列表，不进 Mesh |
| Section Plane / Tag / Scene / Material / Drawing Axes / Hidden | 见 §3.7–§3.9 |
| 自定义属性命名 | 全部加 `su_` 前缀（如 `su_tag`、`su_curve_id`）；随文件保存的模型数据走 `bpy.props` + ID Property，会话状态（推断缓存、上下文栈、上次推拉距离、BVH 缓存）只放内存，绝不写进 ID Property |

**流形/非流形：** SketchUp 是面建模器，允许非流形；bmesh 支持非流形（`link_faces` 可为任意数），与 SketchUp 兼容——这是 bmesh 适合本插件的重要原因。**不得假设流形**，成面/推拉/求交算法均须处理悬边/单面/T 边。Boolean 修改器（EXACT）要求近似流形输入，对非流形可能失败。bmesh 核心算子清单（创建/删除/连接/分裂/挤出/填充/法线/自定义层）→ 调研 B §10.2，锁定版本后须用 `docs.blender.org/api/current/` 逐项复核签名。

**补查清单（实现前须补，调研 B §11 末尾）：** Solid Tools 官方词条（Solid 定义与六布尔工具精确语义）、Components 官方词条全文（Make Component 对话框逐项）、Texture Position 专篇（如有）、Ruby API `Face`/`Edge` 语义交叉验证、Blender current API 复核。

### 4.4 .skp 为什么在外（给 Sen 的解释口径）

- .skp 是 Trimble 的专有二进制格式，从未公开过规范，文件结构随 SketchUp 大版本变化（新版文件旧版打不开是常态）。
- 官方途径是 SketchUp SDK（C API）：需引入 C 库、处理 Windows 构建、遵守 SDK 授权，纯 Python 扩展无法直接用；且 SDK 版本与 SketchUp 版本绑定，维护负担重。
- 社区有逆向工程项目（如 OpenSKP），但保真度（尤其动态组件、复杂材质、场景）与长期维护均无官方保证，且引入第三方逆向库有法律/合规不确定性，需 Sen 明确授权才可评估。
- 替代路径（推荐）：模型交换走 Blender 原生支持的格式（.obj / .fbx / .stl / .gltf / .dae），SketchUp 侧用 Pro 版导出这些格式即可互通；.blend 文件本身就是本插件的“原生格式”，不需要 .skp。
- 如 Sen 坚持要 .skp 互通，应单独立项评估（SDK 路线 vs OpenSKP 路线），不在本方案范围内。

## §5 Blender 插件架构

### 5.1 打包：Extension 格式（唯一格式）

走 Blender 4.2+ Extension 格式（`blender_manifest.toml`），不用已弃用的 legacy `bl_info` 格式（`bl_info` 必须删除）。zip 顶层即 manifest + `__init__.py`，不要多套一层文件夹（构建脚本必须校验）。模块间一律相对 import（Extension 命名空间为 `bl_ext.*`，写死包名会断）；取自身包名用 `__package__`（偏好设置访问 `preferences.addons[__package__]`）。自包含、零编译依赖、零第三方 wheel（Python 版本随 Blender 变：5.0 用 Python 3.11、5.1 起用 Python 3.13，捆绑编译型 wheel 须按版本分别构建，坚决不做）。不要假设扩展目录可写，用户数据走 `bpy.utils.extension_path_user(__package__, create=True)`。manifest 要点：`schema_version = "1.0.0"`、`id` 全小写+下划线（一旦发布不要改）、`version` 语义化、`tagline` ≤64 字符且无结尾标点、`type = "add-on"`、`blender_version_min = "4.2.0"`（Sen 定 4.x–5.x，Extension 最低只能写 4.2.0，见 D6）、`license` 须 Sen 定（建议 GPL-3.0-or-later，与 Blender 插件惯例一致，见 D6 备注）。第一阶段不需要网络/剪贴板权限，不要声明。注册顺序：PropertyGroup → Operator/Panel/Menu/Gizmo/Tool，注销反序；`register()` 禁止访问 `bpy.context` / `bpy.data`（受限 context 会报 AttributeError），只做类注册、菜单 append、keymap 注册（判空，见 §5.5）。注销必须干净移除全部类、菜单、keymap、draw handler、GizmoGroup、Tool、自定义属性，漏清 draw handler 会导致幽灵叠加层。

### 5.3 交互主力：Modal Operator + gpu 绘制

SketchUp 式工具（持续交互、多点输入、实时预览、数字修正）对应 Blender 的 Modal Operator。标准模式：`invoke` 初始化状态 + 添加 draw handler + `modal_handler_add` → `modal` 处理事件 → `execute` 一次性提交几何（供脚本/重做调用，modal 完成时复用同一提交函数）。

统一约定：确认 = 左键 PRESS（判 `event.value == 'PRESS'`，避免 PRESS/RELEASE 各触发一次）；取消 = 右键或 ESC（工具进行中右键语义见决策 D5）；导航键（中键/Shift+中键/滚轮）返回 `PASS_THROUGH`，工具进行中必须能看模型；多点工具每次左键推进显式状态机（如 `WAIT_FIRST_POINT` / `WAIT_SECOND_POINT`），不立即 FINISHED；预览只画不写（鼠标移动只更新 draw handler 数据，不改 mesh，确认时一次性写入，否则每移一次鼠标就产生撤销步）；VCB 输入在 `modal` 里拦截数字键，自建缓冲+显示，不依赖 Blender 的 redo 面板；FINISHED / CANCELLED / 异常都要移除 draw handler（`__del__` 再兜底一次）；改数据的 operator 加 `{'REGISTER','UNDO'}`。

绘制：`SpaceView3D.draw_handler_add`（`POST_VIEW` 画 3D 几何、`POST_PIXEL` 画 2D 文字/标记）；shader 用 `UNIFORM_COLOR` / `POLYLINE_UNIFORM_COLOR` 等新名，**禁止用 `bgl`（5.0 已移除），禁止用带 `3D_` 前缀的旧 shader 名**；`GPUBatch` + `batch.draw`；回调结尾必须恢复 `gpu.state`，否则污染 Blender 自身 UI；文字用 `blf`（中文字体见 §5.8 末尾）；所有 gpu 操作必须在主线程；`bpy.app.background` 为真时不注册 draw handler、不建 gpu 资源（无 GPU 上下文会失败），绘制代码须能被测试跳过。拾取：`bpy_extras.view3d_utils` 屏幕→射线 + `BVHTree` 射线命中（见 §3.1）。

### 5.4 Gizmo 备选

GizmoGroup 只做第二阶段 Move / Rotate / Scale 三轴手柄备选（手柄最终调用同一个 modal operator），第一阶段不做 Gizmo，避免两套交互机制并行。Gizmo 的 `draw_prepare` 拿不到鼠标事件、`test_select` 有已知坑，调试难。不用 Annotation / Grease Pencil 做预览（它们是持久数据，会存进文件、参与撤销）。

### 5.5 快捷键冲突处理：三档总开关 + 数据表驱动

现实：SketchUp 大量无修饰单字母键（L/R/P/M/Q/S 等）与 Blender 单字母键（G/R/S/E/F/P/L/M 等）几乎必然正面冲突，不存在全量共存方案。规则：插件只写 `keyconfigs.addon`，绝不改用户 keymap；注册时保存 `(keymap, keymap_item)` 供注销逐个移除，不删除整个 keymap；`keymaps.new` 的 name 须与已存在 keymap 名一致（`Window` / `3D View` / `Object Mode` / `Mesh`）；headless 时 `wm.keyconfigs.addon` 为 None，注册代码必须判空；modal 内按键在 `modal()` 里直接处理，不走 keymap（Python 不能新建 modal keymap）。

三档总开关（AddonPreferences，档位切换 = 注销旧项 + 注册新项，不靠 `poll` 挡）：

| 档位 | 行为 |
|---|---|
| 0：关闭 | 不注册任何 SketchUp 快捷键，只用菜单/工具栏/N 面板 |
| 1：SketchUp 模式（推荐默认，须 Sen 定，D4） | 注册全套 SketchUp 单字母键；提供“临时切回 Blender 键”开关（组合键或 N 面板按钮）；首次启用时明确告知已接管单字母键、可在偏好设置里关掉 |
| 2：仅组合键 | SketchUp 工具只绑 `Alt+字母` / `Ctrl+Alt+字母` 等不冲突组合键，单字母留给 Blender |

配套：注册时扫描 `keyconfigs.active` 生成冲突报告（列出被覆盖的 Blender 功能，写进偏好设置面板或日志，不静默覆盖）；一键恢复 Blender 默认（注销全部 addon keymap 项）；快捷键表数据表驱动（工具 → 键位），调研 A §7 的 21 项官方默认快捷键表直接填入；每个 keymap 项的 `poll` 再加“当前在 3D 视图且不在文本输入框”判断。第一阶段只保证 Blender 默认预设，Industry Compatible 列为已知未测。

### 5.6 版本判断 + API 适配层（4.x–5.x 兼容，硬性要求）

Sen 已定适配 4.x–5.x，架构须有显式的版本判断与 API 适配层，不得只适配单一版本、不得把版本差异藏在各工具里。

- **适配层位置：** `core/compat.py` 单一模块，所有版本相关分支只出现在这里；各工具/核心模块只调适配层提供的一致接口，禁止散落 `if bpy.app.version` 判断。
- **版本判断：** 以 `bpy.app.version`（`(major, minor, patch)` 元组）为唯一版本来源；同时用 `hasattr` 特征探测作第二道防线（特征探测优先于版本号比较：API 存在与否比版本号更可靠）。
- **API 子集规则：** 只用 4.2+ 与 5.x 共有的 API 子集；凡 5.x 新增 API 须有 4.x 回退路径，凡 4.x 旧 API 已在 5.x 移除则全线禁用。必须遵守的红线（→ 调研 C §1.3，锁定版本后逐项复核 current 文档）：

| 变化 | 对策（全版本统一） |
|---|---|
| `bgl` 在 5.0 被移除 | 一律用 `gpu` 模块 |
| 内置 shader 名 4.0 去掉 `3D_`/`2D_` 前缀 | 用 `UNIFORM_COLOR`、`POLYLINE_UNIFORM_COLOR` 等新名 |
| 字典式 context override 在 4.0 被移除 | 用 `context.temp_override()` |
| `MeshEdge.bevel_weight` / `crease` 在 4.0 被移除 | 走 attribute（`bevel_weight_edge` / `crease_edge`） |
| `mesh.calc_normals()` 在 4.0 被移除 | 不调用，依赖自动法线 |
| 旧 Action API 在 5.0 被移除 | 不做动画则无影响；Scenes 动画用 slotted Action API |
| `bpy.props` 字典式访问在 5.0 被移除 | 用正规 `bpy.props` + PropertyGroup |
| `use_auto_smooth` 在 4.1 被移除 | 按边 Sharp + 面 Smooth 体系（§3.5） |
| 用户 site 目录 5.x 默认不再加载 | 自包含扩展，不依赖外部 pip 包 |
| Python 3.11（5.0）→ 3.13（5.1+） | 零编译依赖、零第三方 wheel，纯 Python 同一 zip 跨版本 |

- **相对稳定的 API（可放心依赖）：** `bmesh`（`from_edit_mesh` / `update_edit_mesh` / `bmesh.ops.*`）、Operator 的 `invoke` / `modal` / `execute` + `bl_options`、Gizmo / GizmoGroup、`SpaceView3D.draw_handler_add` + `gpu`、`mathutils`。
- **版本测试矩阵（每阶段必跑，见 §6）：** 4.5 LTS（4.x 线代表）+ Sen 的 5.1.2 + 5.2 LTS（5.x 线代表）三版本 headless 安装/启用/禁用/核心逻辑测试；5.3.0 只作兼容抽查（非 LTS，不作基准）。4.x/5.x 之间发现做不到或须取舍的 API 差异时，列入决策表问 Sen（D6），**绝不自行决定降级或静默放弃**；提案时未发现已知的不可逾越差异，但每阶段实测后如有发现须如实上报。
- **manifest：** `blender_version_min = "4.2.0"`。4.0/4.1 无法安装 Extension 格式，如 Sen 要求覆盖 4.0/4.1，须另做 legacy `bl_info` 双格式（工作量与维护成本另计），见 D6。

### 5.7 设置与数据存储 + 撤销

**三层存储 + 会话层（→ 调研 C §6.1）：** L1 用户偏好（`AddonPreferences`，跨文件：快捷键档位、推断开关默认、推断颜色/容差、默认单位、图标风格——语言不存偏好，跟随 Blender，见 §5.8）；L2 场景状态（Scene 级 PropertyGroup，随文件：当前 Tag、当前材质、剖面可见性、场景级推断开关、SketchUp 式单位设置）；L3 对象/网格数据（ID 自定义属性 + 正规 `bpy.props`，随对象：组/组件身份、Tag 归属、锁定/隐藏、每面材质）；L0 会话临时状态（WindowManager 级 PropertyGroup 或 operator 实例属性，不保存：当前工具、VCB 缓冲、轴向锁定、推断高亮）。L1/L2/L3 必须用 `bpy.props` + PropertyGroup，不用 Python 全局变量存持久状态；L3 优先正规 `bpy.props`，动态键才用 ID 自定义属性；注销时 `del bpy.types.Scene.sketchup`，不残留。SketchUp 式状态的具体映射（当前材质、Tag 单 Tag 语义强制、组/组件、剖面、参考线、场景）→ 调研 C §6.2 与本方案 §3。

**撤销规则：** 所有改数据的 operator 加 `{'REGISTER','UNDO'}`；一次完整工具动作 = 一个撤销步（modal 移动绝不推撤销步，预览不写数据）；modal 返回 FINISHED 时推撤销步、CANCELLED 时不推且无临时修改可恢复；非 operator 路径手动 `bpy.ops.ed.undo_push`，不许在循环/每帧里调用；`execute()` 内不调带 UNDO 的 `bpy.ops`（用 `bmesh` / `bpy.data` API，避免多余撤销步与 redo 面板混乱）；第一阶段做到“可撤销、不可 redo 改参”，并在方案里写明（redo 改参须把关键参数存为 operator 属性并用属性重算，后续优化）。

### 5.8 界面语言跟随 Blender 设置（硬性要求，用 Blender 自带机制）

**机制（已确认，非推测）：** Blender 自带插件翻译机制 `bpy.app.translations`。插件在 `register()` 里调用 `bpy.app.translations.register(__name__, translations_dict)` 注册翻译字典，在 `unregister()` 里调用 `unregister(__name__)` 注销；字典格式为 `{locale: {("*", msgid): translation}}`，locale 用 `zh_HANS`（简体中文；`zh_CN` 同时注册作别名），msg_key 固定用 `"*"` 上下文——已实测：`pgettext_iface` / `pgettext` 只查 `"*"` 上下文，`("Interface", ...)` / `("Operator", ...)` 等预定义上下文不被查；`zh_CN` 不在 `bpy.app.translations.locales` 与语言枚举中（2026-11-17 探针，4.5.16/5.1.2）。Blender 内部代码负责按当前语言查译文，插件代码只写英文原文（msgid），**不写死语言、不自建语言切换开关**；语言由 Blender 偏好设置（`preferences.view.language`）决定，Blender 语言一切换，插件界面即跟随。含格式化的字符串用 `pgettext_iface` / `pgettext_tip` 系列函数（`pgettext` 家族仅用于此类特殊情况，常规 UI 字符串不直接调用）。管理与收集字符串可用官方 “Manage UI translations” 插件辅助生成字典与 PO 文件。

**实测依据（2026-11-17，本机 headless，四版本全部通过）：** 4.5.16 LTS、5.1.2、5.2.4 LTS、5.3.0 上 `bpy.app.translations` 均存在，含 `register` / `unregister` / `pgettext` / `pgettext_iface` / `pgettext_tip` / `pgettext_data` / `pgettext_n` / `pgettext_rpt` / `locale` / `locales` / `locale_explode` / `contexts`；`register` + `unregister` 往返成功；`bpy.app.translations.locale` 与 `preferences.view.language` 均为 `en_US`。4.x 线机制与 5.x 一致，无差异。**已知限制与对策（2026-11-17 T2 实测，四版本一致；Sen 已定严格统一）：** 与 Blender 内置字符串重名的词条（如 Flip、Orbit、Top），Blender 内置译文优先于插件字典，共 21 条；0.1.1 起全部绘制文字走显式查表，冲突不再影响菜单/面板显示，仅个别类级标签可能显示 Blender 的中文措辞。

**实现规则：** ① 全部 UI 字符串以英文原文为 key，集中放在 `i18n/translations.py` 的字典里，禁止在代码各处散落中文硬编码；② 首期提供 `zh_HANS`（简体中文）与英文（原文即英文，无须译文）双语，其他语言后补（D9）；③ 术语译名对照 Blender 语言包习惯定，工具名以英文原名为准绳；④ 翻译字典缺失某条译文时回退显示英文原文，不报错、不空白；⑤ **未验证项（如实标注）：** headless 只能验证机制存在与注册成功，Blender 语言设中文后插件界面实际显示中文、以及 `blf` 绘制的推断标签/VCB 文字在 Windows 上的中文字体显示（`blf.load` 加载系统字体），只能在 Sen 真机上验证——每阶段验收都含该真机检查项（§6），中文/英文至少都要能跟随。⑥ **显式查表（真机纠正，2026-11-17）：** `layout.operator(text=...)` 的文字 Blender 原样显示、不翻译，`layout.menu(text=...)` 的标题才走翻译；因此全部绘制代码必须用 `translate()` 显式查表后再传给 layout 调用，注册字典只供类级标签（`bl_label`、枚举项）使用。T2 用假布局绘制捕获在中/英双语下逐项核对全部菜单/面板文字。

## §6 分阶段里程碑计划

原则：按依赖排序，地基（推断 + 成面 + VCB）先行，再铺工具；每阶段结束交付可安装的 `.zip` + 测试说明，不攒大包；验收分两栏——这边 headless 验收（含 modal 假事件交互自测）+ Sen 真机验收。

**验收口径变更（2026-11-17，Sen 定）：** Sen 不再逐版真机验收，Ember 用本地 Blender 自测推进，只交付可正常使用的版本。后续各阶段的“Sen 真机验收”栏改为“这边 modal 自测验收”（假事件驱动真实 operator + 网格状态断言，`tests/modal_flows.py`），真机体感类事项（推断颜色、悬停阈值、手感）记为已知待核、不阻塞交付；Sen 只在拿到可用版本后抽查反馈。

**每阶段通用验收（硬性，适用于 P0–P6 的每一阶段）：**

- **双版本安装运行：** 同一个 `.zip` 在 4.x 线（4.5 LTS）与 5.x 线（5.1.2 + 5.2 LTS）上都能安装、启用、禁用、无报错；T2 headless 测试在三个版本上都通过。Sen 真机只装 5.1.2，4.5 LTS 与 5.2 LTS 的安装/启用/核心逻辑走这边 headless 验证，并在测试说明里逐版本列结果。任一版本失败即该阶段不通过；4.x/5.x 差异须取舍时按 D6 问 Sen，不自行降级。
- **语言跟随检查：** 这边 headless 验证翻译字典在三个版本上注册/注销无错；Sen 真机检查：Blender 语言设中文时本阶段新增的插件界面为中文、设英文时为英文（中/英文至少都要能跟随）。未提供译文的字符串回退显示英文原文，不报错。
- **撤销检查：** 本阶段每个改数据的操作都可 Ctrl+Z 撤销一次到位（一次完整动作一个撤销步）。

## §7 框架修订（0.5.0，Sen 2026-11-17 真机反馈后定）

- **SU 模式开关**：插件增加激活开关（头栏 SU Mode 按钮 / N 面板 / F3 切换，默认关闭）。开启 = 进入 SU 建模模式：11 个快捷键生效、吸附自动打开、轴心改 3D 游标、进入编辑模式；关闭 = 全部恢复 Blender 原状（快捷键、吸附、轴心、对象模式）。
- **原生优先**：同类工具优先调用 Blender 原生工具并在其上叠加 SU 行为。Move/Rotate/Scale 改为委托 `transform.translate/rotate/resize`（吸附属性 + 3D 游标轴心 + Ctrl 复制 + Repeat Array 对话框）；Line/形状/PushPull/Offset/FollowMe/Flip/Select/Eraser 无原生等价物，保留自研实现。详见 `research/04-native-first-mapping.md`。
- **快捷键根因（实测）**：0.4.0 及之前把快捷键只注册在 "3D View" keymap，模式 keymap（Mesh/Object Mode）优先分发，事件到不了；且 addon 的 Mesh/Object Mode keymap 不被事件系统查阅。修复：开模式时临时禁用冲突的默认条目（只动冲突项、清单记偏好），关模式逐项恢复。验证用 GUI 真实按键 harness（`tests/gui_key_harness/`）。

*本方案已由 Sen 批准（2026-11-17，D1–D15 按推荐默认值）。§7 修订同样由 Sen 提出并已实施于 0.5.0。*
